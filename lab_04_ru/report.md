
# Отчёт по лабораторной работе 04 

В данной лабораторной работе моделируется срединная часть пайплайна ASR: аудио → акустическая модель (нейросеть) → по кадрам распределения по алфавиту → CTC-loss / декодирование → текст. Акустическая модель заменена фиксированными синтетическими эмиссиями из JSON-наборов, что позволяет сосредоточиться на алгоритме CTC (Connectionist Temporal Classification).

## 1. Цель

Получить практические навыки вычисления CTC-loss: реализовать свёртку путей, forward-рекурсию и декодирование.

## 2. Данные

Каждый кадр — словарь `{символ: вероятность}` с суммой 1. Алфавит `['blank','b','a']`, 3 кадра — всего 27 путей, что позволяет сверить forward с прямой суммой. Blank — строка `'blank'`. Данные синтетические: кадры независимы, нет реальной акустики — упрощение для воспроизводимости.

## 3. Реализованные компоненты

**`ctc_core.py`.** `merge_then_remove` сначала схлопывает соседние одинаковые (кроме blank), затем удаляет blank; возвращает строку. `sum_matching` суммирует вероятности записей с совпадающим transcript. Для `ba` — 5 путей из 27, сумма **0.661**.

**`ctc_forward.py`.** Расширенный таргет `[blank,b,blank,a,blank]`. `incoming_sum` суммирует три вклада без умножения на эмиссию: сохранение состояния, шаг из `state-1`, skip из `state-2` — только если состояние не blank и символы различаются (запрет skip между одинаковыми для `bb`). `terminal_sum` суммирует два последних состояния. Forward-loss для `ba` — **0.661**, совпал с прямой суммой.

**`ctc_decode.py`.** `greedy_path` берёт argmax по кадру (строгое `>`, при равенстве — ранний по алфавиту). `prefix_transitions` раздельно хранит массы `p_blank`/`p_nonblank`: при совпадении последнего символа возвращает `(prefix, p_nonblank·p)` — сохранение, и `(prefix+symbol, p_blank·p)` — расширение; иначе `(prefix+symbol, (p_blank+p_nonblank)·p)`.

## 4. Результаты

| Показатель | Значение |
|---|---|
| Всего путей | 27 |
| Путей для `ba` | 5 |
| Сумма для `ba` | 0.661 |
| Greedy | `a` |
| Beam-5 | `ab` |

Терминальные ячейки alpha (кадр 3): `alpha[3:a] = 0.581`, `alpha[4:blank] = 0.080`; сумма `0.581 + 0.080 = 0.661`. Остальные состояния (0.004, 0.029, 0.086) — выравнивания, не доехавшие до терминальных, в loss не входят они.

Артефакты в `outputs/`: `paths.csv`, `forward_table.csv`, `decoding.csv`, `summary.json`, `forward_table.svg`.

## 5. Ответы на вопросы

**5.1.** Для `ba` — **3^2 = 27** путей, из них **5** подходящих, сумма **0.661**. Терминальные ячейки: `alpha[T-1][3:a] = 0.581` и `alpha[T-1][4:blank] = 0.080`; их сумма равна 0.661.

**5.2.** Greedy → `a`, beam-5 → `ab`. Greedy — точечная оценка одного пути (максимум по кадрам независимо). Beam — суммирование накопленных вероятностей по многим путям с раздельным учётом blank/nonblank-масс; поэтому «видит» транскрипцию, масса которой распределена по нескольким путям.

**5.3.** Ограничения. Данные искусственные: вероятности заданы вручную, кадры друг от друга не зависят. В реальной речи так не бывает — там важны звуки вокруг, а не только текущий кадр. Ещё два минуса: beam отбрасывает часть гипотез и теряет вероятность, а перемножение маленьких вероятностей на длинных последовательностях «обнуляется» (underflow). 

Что можно улучшить. Считать в логарифмах, чтобы не было уменьшения чисел практически до нуля; взять настоящую акустическую модель вместо синтетики; добавить языковую модель в декодер; увеличить ширину луча; попробовать другие подходы (RNN-Transducer, attention-seq2seq).

## 7. Вывод

Реализованы свёртка путей, forward-рекурсия и жадное/beam-декодирование. Корректность подтверждена совпадением forward-loss (0.661) с прямой суммой по путям и различием greedy (`a`) и beam-5 (`ab`), демонстрирующим разницу между точечной оценкой пути и суммарной массой транскрипции. В практических системах требуются лог-пространство, реальная акустическая модель и языковая модель в декодере.
